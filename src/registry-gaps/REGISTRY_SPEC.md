# Registry gaps — 중복 분석 · 티어 · 디자인 키워드

`packages/design-system` 워크스페이스 룰(토큰·CVA·시맨틱·anatomy 정합)과 기존 컴포넌트 조합 가능성을 기준으로 정리했다. **registry-gaps에 있던 부품은 모두 `src/components/`로 이전·구현되었으며**, 이 문서는 설계 근거 레퍼런스로 유지한다.

---

## 공통 디자인 키워드 (3)

**토큰 준수 · 시맨틱 액션 · 합성 우선**

## 공통 한 문장

복잡한 화면은 새 원자보다 **레이아웃(Stack/Grid) + 기존 Button/Input/Modal** 조합을 먼저 고려하고, 반복되는 행위 계약만 anatomy로 고정한다.

## 공통 문단 (3문장)

디자인 토큰과 Tailwind 의미 스케일을 우회하지 않으며, 인터랙션은 `button`·`a`·`input` 등 시맨틱 요소로 둔다. variant가 있으면 `cva`와 `cn()`으로만 합성한다. opaque(Map·비디오 등)는 슬롯으로 두고 DS는 경계·상태·레이블만 책임진다.

---

## 구현 사이클 (부품별 체크리스트)

각 id마다 아래 순서로 진행한다.

1. **중복 재확인** — 이 문서의 조합 열을 다시 읽고, 기존 컴포넌트만으로 충분한지 판단한다.
2. **anatomy 위치** — `src/components/<Pascal>/`에 두고 `registry-gaps` 동명 JSON은 제거한다.
3. **구현** — `'use client'`, `cva`·`cn`, `data-slot="${id}-${partId}"`, 시맨틱 요소.
4. **스토리** — default + variant 매트릭스, `mergeAnatomyMeta`, L1/L2는 `anatomyAssertions` play.
5. **검증** — `pnpm lint`, `format:check`, `type-check`, `validate:ds` (필요 시 `test:stories`).
